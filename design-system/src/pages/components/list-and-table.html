List & table

The divided list is the workhorse of this product — expenses, members, recurring rules, and activity all use it. Tables appear only where a genuine second dimension exists, and they still have to survive a 375px screen.

container
divide-y rounded-lg border — the border and dividers do all the separating.
row
12px padding, justify-between, 12px gap. Title line, then metadata line.
title
text-sm font-medium, truncates. Badges sit inline after it and never shrink.
metadata
text-xs muted, middle-dot separated: date · payer · receipts.
amount
Right-aligned, shrink-0, tabular. It is the column the eye scans.

A navigable row is an <a> filling the whole row — hover tints to muted/60, focus draws the ring. A row with nowhere to go is a <div> with no hover at all: a hover state that leads nowhere is a broken promise. Both are shown above; the settlement row is the non-navigable one.

Numeric columns are right-aligned and tabular. The balance column still carries its word — dropping the label because "it's a table" is the same accessibility failure in a different shape. Wide tables scroll inside their own container; the page body never scrolls sideways.

Rules

Do

Default to the row list. It works at 375px without a single decision, which a table never does.

Don't

Reach for a table to show one value per person. That is a list with a right-hand amount.
