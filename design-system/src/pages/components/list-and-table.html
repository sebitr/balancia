List & table

The divided list is the workhorse of this product — expenses, members, recurring rules, and activity all use it. Tables appear only where a genuine second dimension exists, and they still have to survive a 375px screen — or be drawn from lg only, over the rows a phone's list already draws.

container
divide-y rounded-lg border — the border and dividers do all the separating.
row
12px padding, justify-between, 12px gap. Title line, then metadata line.
title
text-sm font-medium, truncates. Badges sit inline after it and never shrink.
metadata
text-xs muted, middle-dot separated: date · payer · receipts.
amount
Right-aligned, shrink-0, tabular. It is the column the eye scans.

A navigable row is an <a> filling the whole row — hover tints to muted/60, focus draws the ring. A row with nowhere to go is a <div> with no hover at all: a hover state that leads nowhere is a broken promise. Both are shown above; the settlement row is the non-navigable one.

box
The card: 16px radius, a hairline ring, nothing scrolling sideways.
header
36px, 12px uppercase in the muted ink on a muted wash. A sortable column is a button inside its <th>, and the order is the <th>'s aria-sort; the arrow draws it.
rows
52px, 60px with a second line. One <a> per row, on the first text cell, its ::after stretched over the row (position: relative on the <tr>): a click anywhere opens it, a keyboard reaches each row with one Tab, and the table stays a table to a screen reader.
states
Hover and keyboard focus wash the row with --wash-1; focus also draws the ring inset around the whole row. No zebra.
alignment
Text left; every figure right and tabular, never truncated. A column that cannot fit its figure folds onto the second line instead — decided by the table's own box with a container query, not by the window, because a sidebar beside it changes the box and not the window.
footer
12px muted on a lighter wash: how many rows of how many, and in which order.

Rules

Do

Default to the row list. It works at 375px without a single decision, which a table never does.

Don't

Reach for a table to show one value per person. That is a list with a right-hand amount.
